# 开发纪律

## 版本发布与提交

每次功能性修改（新增功能、修复缺陷、行为变更）完成后，必须按以下流程收尾：

1. **升级版本号**：修改本目录 `package.json` 的 `version`。遵循语义化版本：
   - 缺陷修复 → patch 位 +1（如 0.1.11 → 0.1.12）
   - 向后兼容的功能新增 → minor 位 +1（如 0.1.11 → 0.2.0）
2. **更新更新日志**：在 `CHANGELOG.md` 顶部（`# 更新日志` 说明段之后）插入新版本段落，格式遵循 Keep a Changelog：
   - 标题 `## [版本号] - YYYY-MM-DD`（使用当天日期）
   - 变更分类使用 `### 新增` / `### 修复` / `### 变更`
   - 用中文描述变更内容，说明改了什么、为什么改
3. **执行本地 git 提交**：将功能代码、测试、`package.json`、`CHANGELOG.md` 一并提交。提交信息使用英文 conventional commits 风格（如 `fix: ...`、`feat: ...`），与仓库历史保持一致。
4. **排除本地配置**：`config/machine.json` 包含本机绝对路径（hdc、emulatorDeployedDir 等），不得提交。

纯文档修改、测试补充等不影响功能的改动可不升版本，但需正常提交。
