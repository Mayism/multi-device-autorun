# 提示词

请对当前 HarmonyOS ArkUI 景区应用完成门票与“我的”相关页面的一多适配。以窗口宽度为依据实现响应式布局：SM/MD 宽度保持手机和折叠屏原有的单列、全宽布局，LG 平板宽度使用双列列表和居中的 8/12 栅格内容区。

具体要求：

1. 以下列表在 SM、MD 宽度下为 1 列，在 LG 宽度下为 2 列：
   - “门票”页面的门票列表；
   - “我的”页面的功能入口列表；
   - “我的地址”页面的地址列表；
   - “常用旅客”页面的旅客列表；
   - “门票订单”页面的订单列表。
2. 以下内容区在 SM、MD 宽度下占满可用页面宽度，在 LG 宽度下占 12 栅格中的 8 列，并在页面中居中显示：
   - 门票详情进入“预订”后的门票预订内容；
   - 点击“华为用户”进入的个人信息内容；
   - “服务热线”内容；
   - 门票订单详情内容。
3. 使用统一、可响应窗口尺寸变化的断点逻辑。SM 可按小于 600vp、MD 按 600vp 至小于 840vp、LG 按不小于 840vp 处理；不要根据设备名称判断，不要硬编码物理像素宽度。
4. 保留现有数据加载、滚动、点击、返回、编辑、预订和订单等业务行为，并保持现有自动化定位 ID 有效，包括 `ticket_list`、`ticket_reserve`、`function_list`、`personal_info`、`address_list`、`tourist_list`、`hotline`、`ticket_order_list`、`order_detail` 及对应列表子项 ID。
5. 尽量复用工程现有的 `WindowSize`、`AppStorageV2`、ViewModel 或 ArkUI 栅格能力，避免在多个页面复制互不一致的宽度判断。
6. 不要修改或新增测试代码，不要修改 `build`、`.hvigor`、`oh_modules` 等生成目录，只修改实现该适配所需的业务源码。

完成后请分别检查 SM、MD、LG 三种宽度下的上述页面，确保 SM/MD 的现有布局不回归、LG 达到双列或 8/12 栅格要求，并确保工程能够正常编译。
