# 任务：修复信用卡 H5 页面在折叠屏开合时的响应式布局

当前工作区包含两个相互配合的工程：

- `base/`：HarmonyOS ArkWeb 宿主工程，用于加载并展示 H5 页面。
- `web/`：Vue 3 + TypeScript 的数字银行 H5 工程。

请结合两个工程理解页面的承载方式，并在合适的工程中完成修复。

## 问题描述

信用卡频道采用基于容器宽度的 `rem` 响应式布局。页面首次进入时显示正常，但当折叠屏在页面存续期间发生折叠或展开、导致 ArkWeb/H5 容器宽度变化时，页面的缩放基准没有及时跟随更新。

这会造成窄屏状态下布局仍沿用展开状态的尺寸，底部“最低还款”和“立即还款”按钮可能溢出或被裁剪；设备重新展开后，页面尺寸和位置也可能无法正确恢复。

## 修复要求

1. 页面挂载后，持续感知实际承载信用卡频道的 H5 容器宽度变化，并及时刷新响应式缩放基准，不能只在首次挂载时计算一次。
2. 折叠到较窄宽度后，页面内容应随可用宽度缩放；“最低还款”和“立即还款”两个按钮必须完整显示在 Web 可视区域内，并保留合理的左右边距。
3. 设备重新展开后，Web 页面及两个按钮的尺寸、水平位置应恢复到展开前的状态，不能残留折叠状态下的缩放结果。
4. 宽度快速连续变化时应避免重复、无效的同步布局计算；忽略无效宽度，并避免对相同有效宽度反复更新。
5. 保持现有视觉样式、页面结构、导航和交互行为不变。手机及普通非折叠场景应继续正常显示，两个还款按钮保持可点击。
6. 做好组件生命周期清理：页面卸载后不应残留尺寸监听或待执行的异步回调，并应恢复该页面临时修改的全局样式，避免影响其他页面。

## 实现约束

- 使用现有技术栈和响应式布局机制，尽量保持改动范围小且职责清晰。
- 不要通过硬编码特定设备宽度、固定像素布局、强制刷新页面或重新挂载整个应用来规避问题。
- 不要修改与本问题无关的业务功能或界面文案。

## 验证建议

- 在 `web/` 中完成依赖安装、构建和已有测试，确保 TypeScript/Vue 工程可以正常编译。
- 验证信用卡频道在展开、折叠、再次展开的连续过程中能够动态缩放并恢复。
- 验证手机宽度下页面可正常进入，两个还款按钮完整可见且可交互。
