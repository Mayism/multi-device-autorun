# 提示词

请对当前 HarmonyOS ArkUI 笔记工程完成一多适配。先加载并遵循 `harmonyos-multi-device-adaptation` skill；实施前阅读 `test_patch.patch` 了解验收场景，并使用工程已有的窗口管理、断点、导航与笔记编辑能力完成适配。

布局判断必须基于窗口尺寸和项目已有的断点机制，不得依赖具体设备名称或固定物理像素。需要区分 LG 平板与 PC/2in1：两者可能处于相同窗口断点，但页面布局目标不同。

具体要求：

1. 在 SM 手机与 MD 折叠屏展开断点下：
   - 笔记列表为全屏/主内容布局，宽度至少占窗口宽度的 80%；
   - 分类列表为单列，分类项宽度接近分类列表完整宽度；
   - 保持现有浏览笔记、进入分类、新建/编辑笔记和返回导航行为。
2. 在 LG 平板断点下（非 PC 三栏模式）：
   - 笔记列表切换为侧栏，宽度不超过窗口宽度的 50%；
   - 分类列表为 3 列，分类项宽度约为分类列表宽度的三分之一；
   - 侧栏与内容区域随窗口变化稳定重排，不遮挡或破坏既有编辑流程。
3. 在 PC/2in1 模式下：
   - 使用三栏布局，笔记列表作为中栏，宽度约占窗口宽度的 25%–34%；
   - 自由调整窗口尺寸前后，笔记列表相对窗口的宽度比例保持稳定；
   - 保留分类选择、笔记选择、编辑、未保存内容提示及数据刷新行为。
4. 保持测试依赖的 `note_list`、分类列表及其子项等组件 ID 和可访问结构有效；不要为通过测试硬编码某个模拟器尺寸。
5. 不要修改或新增测试代码，不要修改 `test_patch.patch`、`golden_patch.patch`、`metadata.json`，也不要修改 `build`、`.hvigor`、`oh_modules` 等生成目录；只修改实现适配所需的业务源代码。

完成后，检查 SM、MD、LG 与 PC 下的笔记列表占比、分类列数、窗口 resize 稳定性以及导航/编辑交互，并尽可能执行适当的编译验证。
